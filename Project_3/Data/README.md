# FloodNet Data
Link to dataset GitHub repo: https://github.com/BinaLab/FloodNet-Supervised_v1.0
## DATA SUMMARY
Our dataset contains 2,343 high-resolution drone images of Hurricane Harvey flooding, each paired with a pixel-level mask covering 10 classes, including flooded and non-flooded buildings and roads. The images come in official training (1,445), validation (450), and test (448) sets, which we keep unchanged. We will resize and crop the images, train a U-Net to predict a class for every pixel, and convert the predicted masks into percent-flooded values and a low, moderate, or high flood impact score for buildings and roads. The project tests whether segmentation can produce a reliable score, not whether it can assess damage in general. Results apply to Harvey imagery from Fort Bend County, Texas, and nearby areas, and may not carry over to other storms or regions; human-drawn labels may also contain errors. The dataset is about 13 GB, so we did not download it to our own computers. It is hosted by the authors at github.com/BinaLab/FloodNet-Supervised_v1.0, which links to a Dropbox folder, and we access it by loading it into temporary storage in Google Colab. Our notebooks and results will be kept in a GitHub repository shared with the group members and instructor.
## PROVENANCE
We used the FloodNet Supervised v1.0 semantic segmentation release, which contains images taken with a DJI Mavic Pro drone at about 200 feet between August 30 and September 4, 2017, over Fort Bend County, Texas, and other areas hit by Hurricane Harvey. Each image is paired with a pixel-level mask labeled into 10 classes. On November 12, 2026, we loaded the release into Google Colab from the Dropbox link on the authors' GitHub page, which gave 2,343 images and 2,343 masks. We kept the official train (1,445), validation (450), and test (448) folders unchanged and moved no files between splits. We verified that every image has exactly one mask with a matching filename, that mask values fall between 0 and 9, that image and mask sizes match, and that no files are corrupt; all four checks found no exceptions. We recorded file counts and a SHA-256 checksum for each folder, and since the data is reloaded into Colab each session, the checksums let us confirm every copy is identical. We never modify the original files; resizing, cropping, and augmentation write to separate folders. The repository does not document annotation quality checks, and a thumbnail comparison flagged 72 candidate near-duplicate pairs across splits, so label quality and split independence remain assumptions.
